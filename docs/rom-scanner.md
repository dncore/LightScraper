# Batocera ROM Library Scanner

LS-T002 adds a standalone, read-only Go scanner under
`internal/library/scanner`. It discovers Batocera system directories from a
user-selected ROM library root and returns matching ROM file metadata in
memory. It does not write files, use SQLite business tables, update
`gamelist.xml`, call a provider, or start a task scheduler.

## Input and directory model

The input is the ROM library root, normally Batocera's `roms/` directory
(`/userdata/roms` or the `roms/` folder on a Batocera share). It is **not** the
`/userdata` directory.

- Every immediate child directory of the root is a candidate system directory.
- The system ID is the directory name, for example `nes` or `snes`. The scanner
  does not read `es_systems.yml`, maintain a hardcoded platform table, or infer
  a platform from a game.
- A system's extension source is only `<system>/_info.txt`.
- Root-level `bios` directories are ignored, as are hidden entries whose name
  starts with `.`.
- Root-level ordinary files are ignored.
- A system directory is included in `ScanResult.Systems` even when its
  `_info.txt` is missing or invalid. In that case `ROMs` is empty and an issue
  explains why; the scanner does not fall back to guessed extensions.
- Scanning is recursive inside a system directory. Subdirectories are walked;
  only regular files matching the system's extensions are returned.

## `_info.txt` evidence and parser contract

### Official documentation

The Batocera Wiki
[`add_games_bios`](https://wiki.batocera.org/add_games_bios) (page metadata
`dateModified: 2023-07-20`) states that each system has an `_info.txt` and that
NES accepts `.7z .nes .zip`. It points readers at `roms/nes/_info.txt`, but
does not specify the complete line grammar.

### Batocera 43.1 stable generator

- Tag: `batocera-43.1`
- Commit: `155c2d8d304cbb53db52e9479dcf683392821d5c` (2026-05-29)
- Generator:
  [`python-src/batocera-es-system/batocera_es_system/roms.py`](https://github.com/batocera-linux/batocera.linux/blob/batocera-43.1/python-src/batocera-es-system/batocera_es_system/roms.py)
- NES metadata:
  [`es_systems.yml` L195-L210](https://github.com/batocera-linux/batocera.linux/blob/batocera-43.1/package/batocera/emulationstation/batocera-es-system/es_systems.yml#L195-L210)

The 43.1 generator writes a quoted, space-separated extension list and then
concatenates `comment_en` immediately after the closing quote. The exact
generated NES line is therefore:

```text
ROM files extensions accepted: ".nes .unif .unf .zip .7z"For more info: https://wiki.batocera.org/systems:nes
```

This is not a parser mistake. The fixture
`internal/library/scanner/testdata/batocera-43.1-nes_info.txt` preserves that
concatenation and has no inserted newline. The parser extracts the first pair
of double quotes, so the trailing comment is ignored.

### Current master generator

- Commit: `1270be9ade8154079b71bbcfd9476c35e6a0d0d1` (2026-11-04)
- Generator:
  [`python-src/batocera-es-system/batocera_es_system/roms.py`](https://github.com/batocera-linux/batocera.linux/blob/master/python-src/batocera-es-system/batocera_es_system/roms.py)

Master supports two additional output forms:

```text
ROM files extensions accepted: .nes .unif .unf .zip .7z
```

and, when emulator/core metadata exists:

```text
ROM files extensions accepted:
- libretro/fceumm: .7z .nes .unf .unif .zip
- libretro/nestopia: .7z .nes .unf .unif .zip
```

The scanner merges all valid `- emulator/core: extension-list` lines. It
requires a single-token name and the exact bullet structure; it stops at the
first non-bullet line, so later comments cannot become extension sources.
The master form is forward compatibility; 43.1 is the primary stable target.

### Fixtures are derived, not image samples

The fixtures and their source hashes are documented in
`internal/library/scanner/testdata/README.md`. They were generated by invoking
the official generator functions with official NES metadata (43.1), or the
official master generator logic (inline and multiline). They are **not**
extracted from a Batocera distribution image and must not be described as
byte-level image samples. The 4.33 GB 43.1 image was not downloaded.

The parser accepts:

- quoted inline values (43.1 and compatible output);
- unquoted inline values (master with no emulator metadata);
- contiguous emulator/core lines (master with metadata);
- English first, French fallback only if English yields no usable extensions.

It normalizes extension names to lowercase, requires a leading `.`, accepts
ASCII letters/digits plus `-`, `_`, and `+` in the extension body, ignores
blank and malformed tokens, deduplicates, and sorts the result. Comments,
separators, URLs, and ordinary prose are never returned as extensions. There
is no default or hardcoded extension table.

## Traversal, path, and safety policy

- The root must exist, be a directory, and be readable. Root-level failures are
  returned as errors.
- `ScanResult.Root` is the absolute logical path of the selected root.
- A root that is a user-selected symbolic link is accepted. `os.Stat` follows
  that explicit entry; result paths remain under the logical root path.
- Descendant symbolic links are never followed. This covers system
  directories, ROM files, nested directories, and `_info.txt`. Following a
  root symlink does not authorize following links below it.
- Symlinks are counted in `ScanStats.SkippedSymlinks`. A symlinked `_info.txt`
  produces an `info_symlink` issue and the system is not scanned.
- Hidden files and directories are those whose names begin with `.`. They are
  skipped and are not recursed into. Dot-prefix behavior is used on every
  platform; Windows hidden attributes are not inspected.
- `_info.txt`, `gamelist.xml`, `README`, `README.*`, and `*.log` are treated as
  control/documentation files and are not ROM entries. An ordinary `.txt`
  file such as `notes.txt` is still considered when `.txt` is advertised.
- The scanner only calls read/stat/readdir operations. It never writes,
  renames, moves, deletes, or changes permissions on a ROM or Batocera file.
- Systems are sorted by ID; ROM entries are sorted by normalized relative path
  (with `AbsolutePath` as a tie-breaker). Extension sets are sorted.

`ROMEntry.AbsolutePath` is a native absolute path. `RelativePath` is relative
to the system directory and uses `/` as the API separator for stable,
cross-platform results. `DisplayName` only removes the filename's final
extension; it does not clean regions, revisions, or multi-disc relationships.

## API

```go
result, err := scanner.Scan(ctx, root)
```

- `ctx` is checked before root access, during traversal, and at completion.
- A canceled scan returns the partial `ScanResult` plus a context error;
  `errors.Is(err, context.Canceled)` works and `ScanResult.Cancelled` is true.
- Root errors are ordinary wrapped errors.
- Per-system and per-file problems are `ScanIssue` values in
  `ScanResult.Issues` and the corresponding `SystemResult.Issues`.

Data structures are defined in `internal/library/scanner/types.go`:
`ScanResult`, `SystemResult`, `ROMEntry`, `ScanIssue`, `ScanStats`.
`SystemResult.ROMCount` mirrors `len(SystemResult.ROMs)` for callers that only
need the count.

Issue phases are `system`, `info`, `walk`, and `stat`. Issue kinds currently
include:

| Kind | Meaning |
| --- | --- |
| `info_missing` | system has no `_info.txt`; no ROMs scanned |
| `info_unreadable` | `_info.txt` could not be read |
| `info_invalid` | no usable extension section was found |
| `info_symlink` | `_info.txt` was a symlink and was not followed |
| `info_not_regular` | `_info.txt` was not a regular file |
| `walk_error` | a directory could not be read during recursion |
| `entry_stat_failed` | a matching file disappeared or could not be statted |

An issue is not a fatal error for the whole scan; other systems continue.

## Tests

The package tests use temporary directories and generated fixture files:

- exact 43.1, master inline, and master multiline parser fixtures;
- multiple systems/extensions, recursion, case-insensitive matching,
  Unicode/space paths, hidden entries, `bios`, control files, empty systems,
  and missing/no-match cases;
- missing, invalid, unreadable, non-regular, and symlinked `_info.txt`;
- file-stat failure after enumeration, directory-read failure, root symlink,
  descendant file/directory symlinks, and a symlink loop;
- context cancellation before and during traversal;
- stable ordering;
- read-only snapshot comparison before/after scanning.

Run:

```bash
go test ./internal/library/scanner
go test -tags webkit2_41 ./...
go test -race -tags webkit2_41 ./...
go vet -tags webkit2_41 ./...
test -z "$(gofmt -l main.go assets_*.go internal)"
```

## Not supported

- ROM content identification, hashes, or archive inspection.
- Grouping cue/m3u/chd files into a single game or following cue references.
- Directory-as-game formats.
- `gamelist.xml` reads/writes (LS-T003).
- Metadata providers, downloads, task queues, or persistence.
- UI integration. LS-T002 returns in-memory data only.
